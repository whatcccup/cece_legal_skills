# 合同脱敏规则清单

> 本文件是脱敏规则的**唯一配置源**，供 `contract_sensitive_detector.py`（识别）与
> `contract_redactor.py`（改写）共同读取。**直接编辑本文件即可增删改规则，无需改代码。**
>
> 运行方式（二选一）：
> 1. 把本文件与脚本放在同一目录，工具自动加载；
> 2. 显式指定：`python contract_sensitive_detector.py 合同.docx --rules 脱敏规则清单.md`
>
> 想跳过本文件用内置默认：`--rules /dev/null`（macOS/Linux）。

## 列说明

| 列 | 含义 |
|----|------|
| 规则名 | 类型 ID（已有 ID 修改属性；新 ID 必须在最后一列填正则） |
| 严重度 | 高 / 中 / 低（用于复核页按高中低分类筛选） |
| 掩码方式 |给人看的说明，程序不解析 |
| 掩码参数 | 分号分隔的 `key=value`。可用 key：`keep_head`（保留前 n 位）、`keep_tail`（保留后 n 位）、`replacement`（整串替换，如 `[已脱敏]`）、`mask`（命名策略，见下表）。`replacement` 与 `mask` 互斥，后写的生效 |
| 默认启用 | 是 / 否 |
| 正则 | 仅**新增**规则时必填。正则里的竖线请写成 `\|` |

命名策略（`mask=`）：`person` 姓氏+`**`、`passport` 留首字母、`hk_id` 香港身份证、
`landline` 留区号后 4 位、`address` 留省市区县、`ipv4` 留第一段、`mac` 留前 2 位、
`secret` 全遮 `[已脱敏]`、`amount` → `¥******.**元`、`email` 留首字母与域名。

## 如何新增规则

在表格末尾追加一行，`规则名` 用新的英文 ID，最后一列填正则即可，例如：

```
| 28 | EMPLOYEE_NO | 商业信息 | 中 | 员工工号（A+8位数字） | 保留前2后3 | keep_head=2; keep_tail=3 | 是 | 工号\s*[A-Z]\d{8} |
```

保存后重跑识别命令即生效；复核页面会自动出现新类型供勾选。

## 与复核页/改写工具的关系

- `contract_sensitive_detector.py`：按本表识别候选，生成复核页（脱敏前后对比）；
- 复核页勾选（按高中低分类筛选）→ 确认后生成 `*.selection.json`；
- `contract_redactor.py`：读取选择文件，对 docx/pdf 执行真正的脱敏改写。

## 占位符编号规则（重要）

脱敏产物统一使用 `[类型标签#N]` 形式的**占位符**（例如 `[自然人姓名#1]`、
`[组织机构名称#2]`），并同时产出 `mapping.json` 用于一键还原。

编号遵循两条铁律：

1. **同一个实体，整篇共用一个编号。**
   张三在第 1 段和第 30 段出现，都写成 `[自然人姓名#1]`；
   不会出现「人1 / 人7 / 人23」这种一个人占多个号的情况。
   —— 否则一份合同会冒出几十个人名编号，审核时无法判断「人7 是不是刚才的人1」。

2. **不同实体，各自占号，编号按文档中首次出现的先后顺序分配。**
   文中第一个出现的人是 `#1`，第二个是 `#2`；机构名、信用代码等各自独立编号。

### 简称（同一主体的另一种写法）

企业名称常写成「北京星海智能科技有限公司（以下简称"星海智能"）」，正文则用简称。
**全称与简称共用同一个编号**，写法包括：

- 显式定义：紧跟全称之后的 `（以下简称"X"）` / `（下称 X）` / `（简称 X）`；
- 自动推算的字号：由全称去掉行政区划前缀与机构类型后缀得到，例如
  `北京星海智能科技有限公司` → `星海智能科技`；
- 分支机构：`XX 有限公司上海分公司` 与 `XX 有限公司` 视为同一主体。

不同主体不会被误并（例如 `中国工商银行` 与 `中国银行`、`招商银行` 与 `中信银行`
各自独立；`上海分公司` 与 `北京分公司` 各自独立）。

### 还原

- 产物 docx 内嵌了 mapping（`customXml`），同目录也会落一份 `<名字>.mapping.json`；
- 还原时同一个占位符会**按出现位置**还原成各自的写法
  （全称还原成全称、简称还原成简称），因此还原稿与原文逐字一致；
- 可直接把脱敏稿拖回复核页选「还原」，或命令行加 `--restore`。

### 输出与保存（复核页底部）

点「确认并执行脱敏」后，**默认把两个文件一起保存**，不需要用户再选：

| 文件 | 是否默认 | 用途 |
|---|---|---|
| `xxx_脱敏.docx` | 是（必选） | 交付给对方的脱敏稿 |
| `xxx_脱敏.docx.mapping.json` | 是（可取消勾选） | 还原用的对照表，建议一并留存 |

保存位置有两种，**优先文件夹**：

1. 先点「选择保存文件夹…」（建议选**上传合同所在的文件夹**）→ 两个文件直接写进去，
   不再弹下载框；浏览器会记住这个文件夹，下次默认还是它。
2. 不选文件夹 → 两个文件自动下载到浏览器默认下载目录
   （Chrome 首次可能提示「允许多个文件下载」，允许一次即可）。

> 即使 mapping.json 没保存也没关系：映射材料同时**内嵌在脱敏稿内部**，
> 之后把脱敏稿拖回本工具即可一键还原。

复核页里逐个点掉的高亮位置会**真的不替换**（服务端按绝对偏移精确匹配，
所以预览看到什么，产物就是什么）。若白名单因文档被改动而完全对不上，
程序会退化为「按类型全量脱敏」而不是静默输出一份没脱敏的文件。

### 检查清单

改完规则后建议跑一遍这几条命令确认没有破坏编号、还原与保存：

```bash
python contract_sensitive_detector.py --selftest          # 识别 + 编号一致性
python tests/test_entity_consistency.py                   # 同名同号 + 还原逐段一致
python tests/test_app_e2e.py                              # 上传→脱敏→下载→还原全链路
python tests/test_output_download.py                      # 两个文件都能下载 + 点掉的位置不替换
node   tests/test_save_output.js                          # 确认后两个文件都保存（含退化为下载）
```
